# 标签页管理功能 — 设计文档

**日期**: 2026-06-08
**状态**: ✅ 已确认

---

## 1. 概述

在主窗口内增加标签页（Tab）管理能力。打开的笔记以标签页形式展示在编辑区顶部，用户可点击标签切换文档、点击 × 关闭标签、右键批量操作。侧边栏笔记列表保留，与标签页互补——点击列表中的笔记会在标签栏中打开或激活对应标签。

## 2. 当前架构

- **框架**: Tauri 2 + React 19 + TypeScript（前端），Rust（后端）
- **窗口模型**: 多窗口——主窗口（MainWindow）、便签窗口（NotePad）、磁贴窗口（Tile）、AI 聊天窗口
- **主窗口结构**: 侧边栏（分类 + 笔记列表）+ 中间编辑器区（MarkdownEditor + MarkdownPreview + OutlinePanel）
- **编辑器状态**: 当前在 `MainWindow` 中维护 `selectedId`、`content`、`saveState` 等状态，一次只能编辑一个笔记

## 3. 设计目标

- 用户可在同一窗口内打开多个笔记，通过标签页切换
- 标签页支持横向滚动（笔记数量多时）
- 右键菜单支持批量关闭操作（类似 VS Code）
- 退出时记住打开的标签，下次启动恢复
- 沿用现有编辑器组件，不引入新的编辑器实现
- 侧边栏列表与标签页联动

## 4. 数据模型

### 4.1 Tab State

```ts
interface TabState {
  noteId: string; // 笔记 ID
  title: string; // 显示标题（随改名更新）
  content: string; // 编辑器当前内容（切换 tab 时保留）
  saveState: SaveState; // "idle" | "dirty" | "saving" | "saved" | "error"
}
```

### 4.2 新增状态（MainWindow 内部）

```ts
const [tabs, setTabs] = useState<TabState[]>([]);
const [activeTabId, setActiveTabId] = useState<string | null>(null);
```

- `activeTabId` 决定编辑区渲染哪个笔记
- 侧边栏 `selectedId` 跟随 `activeTabId` 联动
- 每个 tab 独立维护自己的 `content` 和 `saveState`

## 5. 标签栏 UI 与交互

### 5.1 布局

```
┌────────────────────────────────────────────────────────────┐
│ ← 标签1 ×  标签2 ×  标签3 × ... →              [+ 新标签页] │
└────────────────────────────────────────────────────────────┘
```

### 5.2 基础交互

| 操作                   | 行为                                               |
| ---------------------- | -------------------------------------------------- |
| 点击标签               | 切换 `activeTabId`，更新编辑区内容，侧边栏同步选中 |
| × 按钮                 | 关闭标签，dirty 状态时弹确认框                     |
| \+ 按钮                | 新建笔记并打开为新标签                             |
| 鼠标滚轮（标签栏区域） | 横向滚动标签列表                                   |
| 标签宽度               | 自适应，最大宽度截断 + tooltip 显示完整标题        |
| 当前激活标签           | 高亮样式区分                                       |
| 打开/激活标签时        | 自动滚到可见区域                                   |

### 5.3 从侧边栏点击笔记

- 笔记已在标签列表中 → 激活对应标签
- 笔记不在标签列表中 → 新建标签并激活

### 5.4 横向滚动

- 标签过多时两端出现渐变遮罩，指示还有更多标签
- 支持鼠标滚轮横向滚动和触控板左右滑动

### 5.5 右键菜单（批量操作）

| 菜单项     | 行为                                                |
| ---------- | --------------------------------------------------- |
| 关闭       | 关闭当前标签                                        |
| 关闭其他   | 保留当前标签，关闭其余                              |
| 关闭右侧   | 关闭当前标签右侧的所有标签                          |
| 关闭所有   | 关闭全部标签                                        |
| 关闭已保存 | 关闭所有 `saveState !== "dirty"` 的标签（无需确认） |

- 遇到未保存标签时，第一个弹出确认框；确认框提供「全部保存并关闭」选项

## 6. 编辑器状态管理

### 6.1 切换标签

1. 将当前 tab 的最新 `content` 和 `saveState` 保存到 `tabs` 数组
2. 从 `tabs` 取出目标 tab 的状态，恢复到编辑器
3. 侧边栏 `selectedId` 同步更新

### 6.2 自动保存兼容

- `noteAutoSave` 配置开启时，切换 tab 自动触发保存
- 保存失败时标记 `saveState: "error"`，不阻塞切换

### 6.3 大纲面板联动

- 大纲显示的标题结构跟随当前激活标签的笔记内容
- 切换标签时大纲重新解析

## 7. 标签状态持久化

### 7.1 存储

- 退出应用时将标签列表（仅 `noteId` 数组 + `activeTabId`）写入 `AppConfig`
- 每个 tab 的 `content` 不持久化（依赖 noteAutoSave 或手动保存），避免存储负担

### 7.2 恢复

- 启动主窗口时从 config 读取 `openTabs` 和 `activeTabId`
- 恢复标签列表，每个 tab 标题从文件系统懒加载
- 切换到某个 tab 时才从后端拉取完整内容

### 7.3 边界

- 恢复时如果某个笔记已被删除，跳过该标签
- 如果恢复后 `activeTabId` 对应的笔记不存在，激活第一个标签

## 9. 设计决策记录

| 决策       | 选择                | 理由                                       |
| ---------- | ------------------- | ------------------------------------------ |
| 架构方案   | 纯 React state 驱动 | 改动最小，与现有 MainWindow 模式契合       |
| 标签位置   | MainWindow 内部     | 标签状态与编辑器状态在同一组件，数据流简单 |
| 持久化位置 | AppConfig           | 复用现有配置存储通道，无需额外 Tauri 命令  |
| 便签窗口   | 暂不动              | 后续独立重构，与标签页功能解耦             |
